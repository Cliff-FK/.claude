# Architecture de contenu — topic clusters + money pages

## Topic clusters (hub-and-spoke) — le modèle dominant
Remplace les vieux silos rigides. Construit l'**autorité topique** que lisent moteurs ET LLM.

- **Pillar page** : couvre un sujet large à haut niveau, sert d'autorité canonique, lie vers chaque cluster. (Les « 3 000-5 000 mots » qui circulent sont indicatifs — viser la **couverture complète**, pas un compteur.)
- **Cluster pages** : creusent chaque sous-sujet. **Chaque cluster lie vers le pillar** avec une ancre contenant le mot-clé cible du pillar.
- **Maillage interne** = le tissu conjonctif qui transmet l'autorité topique. C'est le levier sous-exploité n°1.

### Cluster ≠ silo
Le cluster organise par **sujet + intention** (relié par hub) ; le silo par **section de site** sans forcément relier les pages. Le cluster gagne en 2026.

## Money pages vs contenu
- **Money pages** : home, page produit, pricing, « alternative à X », comparatifs « best X » / « X vs Y ». Intention commerciale/transactionnelle, optimisées conversion ([[copywriting-landing]]).
- **Blog / clusters** : informational, haut de funnel, **irrigue** les money pages par maillage descendant.

## Le filon comparatifs/alternatives (le plus rentable pour un plugin)
« best [catégorie] plugin », « [vous] vs [concurrent] », « alternative to [concurrent] » : forte intention commerciale, conversion directe, très citées par les IA quand on cherche un outil. Critères à couvrir dans ces pages : fonctionnalités, vitesse/perf, coût total, maintenance, compatibilité.

## URL
Courtes, lisibles, structurées, sans bourrage de mots-clés. Pas d'EMD comme « levier » (effet résiduel marginal depuis 2012).

## Gotcha duplication (spécifique plugin)
**Ne pas copier le readme.txt wordpress.org sur le site produit** : pas une « pénalité » mais dilution + risque de canonicalisation vers wordpress.org (autorité supérieure → c'est lui qui rankera). Réécrire entièrement la copy du site.
